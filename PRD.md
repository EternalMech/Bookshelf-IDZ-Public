# PRD · «Между строк»

## Идея и пользователь

Небольшая личная книжная полка для человека, который забывает, что хотел
прочитать, и хочет отделить планы от начатых и законченных книг. Пользователь
добавляет книгу за несколько секунд и видит актуальный список в одном месте.

Ценность: понятный список без социальных функций, регистрации и настройки сервера.
Основная платформа — браузер на компьютере; узкие экраны также поддерживаются.

## Функции и объём

| Функция | Промежуточная версия | Итоговый этап |
|---|---|---|
| Добавить название и автора | Реализовано | Сохранено |
| Изменить статус: план / читаю / прочитано | Реализовано | Сохранено |
| Найти по тексту и отфильтровать по статусу | Реализовано | Сохранено |
| Удалить книгу с подтверждением | Реализовано | Сохранено |
| Прототип авторизации | Не требовался | Вход с демонстрационным логином и паролем, выход |

Итоговая версия оставляет localStorage: полка предназначена для одного браузера,
синхронизация и отдельный сервер для этого сценария не нужны.

## Основной сценарий

1. Пользователь открывает локально запущенное приложение в браузере. При
   первом запуске вводит логин `demo` и пароль `bookshelf`, нажимает «Войти».
   После короткой имитации входа открывается полка.
2. Нажимает «Добавить книгу» и вводит название и автора.
3. Нажимает «На полку». Книга сохраняется и появляется первой в статусе
   «Хочу прочитать»; поиск и фильтр сбрасываются, чтобы результат был виден.
4. Нажимает «Начать читать», затем «Отметить прочитанной».
5. Выбирает фильтр «Прочитано» и видит книгу в списке.
6. Перезагружает страницу или повторно запускает приложение по тому же URL:
   вход, книга и её статус сохраняются, фильтр по умолчанию — все.
7. При необходимости нажимает «Выйти». Полка остаётся в браузере и снова
   доступна после повторного входа.

Ожидаемый результат: пользователь добавил свою книгу, прошёл путь до прочтения
и не потерял введённые данные после перезагрузки.

Два экрана: демовход и полка. На полке — диалог добавления и подтверждение удаления.
Три информационных счётчика вычисляются из списка, не требуют отдельных данных.

## Состояния и ограничения ввода

- Название: обязательное, до 100 символов; автор: обязательный, до 80 символов.
  Пробелы по краям убираются; строка из пробелов не считается значением.
- Пустая форма остаётся открытой, показываются подсказки у полей.
- Поиск без учёта регистра по названию и автору, применяется вместе с фильтром.
- Если список пуст — предложить добавить первую книгу. Если нет результатов
  поиска — предложить сбросить фильтры. Удалённый пустой список не засеивается заново.
- Ошибка чтения: отдельное состояние с повторной попыткой, данные не стираются.
- Ошибка записи: не показывать успех и не менять список; дать повторить действие.
- Во время записи повторное изменение недоступно.
- Одинаковые названия допускаются: разные издания могут быть отдельными записями.
- Пустое поле или неверная пара не открывают полку. Пропуски подсвечиваются под
  соответствующими полями, неверные данные — сообщением «Неверный логин или пароль».
  Во время имитации входа повторная отправка недоступна. При ошибке хранения
  можно повторить действие, сессия не считается изменённой.

## Техническое решение и данные

Flutter 3.44.2, Dart 3.12.2, Material 3. Только web-платформа.
Без backend, облачной БД, секретов, внешних API и платных сервисов.
Простая структура: модель Book, BookStore, контроллер состояния и экран.

Book: `id`, `title`, `author`, `status` (planned/reading/finished), `createdAt`,
`palette` (вариант нарисованной обложки). Документ хранения имеет `version: 1`.
Список сериализуется в JSON и записывается через `shared_preferences` в браузерное
localStorage, ключ `between_lines.books.v1`. Пустой список — валидное сохранение.
При отсутствии записи один раз создаются шесть примеров из известных книг;
это демонстрационные данные, не пользовательские записи и не внешний API.

Mock-авторизация не проверяет личность и не изолирует данные разных людей.
Пара `demo` / `bookshelf` общедоступна и проверяется в приложении. Значения из
формы никуда не отправляются и не сохраняются. В ключе
`between_lines.demo_session.v1` лежит только булева отметка входа. Выход
сбрасывает её, но не меняет `between_lines.books.v1`.

Хранилище привязано к origin: **http://localhost:5173**. Данные остаются при
перезагрузке/перезапуске по тому же адресу в том же профиле браузера. Очистка
браузера, приватный режим, другое устройство, hostname или порт не сохраняют
доступ к прежней полке. Это не резервное хранилище и не защита персональных данных.
